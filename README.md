# My Hub — Notes

React + Ant Design + Vite app for managing **Notes / Tasks**. Data is stored on **Cloudflare KV** (safe, persistent, accessible anywhere) — no localStorage for data storage.

- **Live:** https://my-hub-ode.pages.dev
- **Repo:** https://github.com/nguyen-hoang-tam/My-Hub

## Features

- **Authentication** — login / register forms, session token stored in localStorage, logout from the header dropdown. Accounts are stored server-side in KV (hashed passwords).
- **Notes / Tasks (Dashboard)** — default page after login: manage tasks by status (New / In progress / On hold / Completed / Cancelled), departments (Dev / BA / QC / UXUI), deadlines, images, Table / Kanban views (drag & drop). CRUD is persisted on Cloudflare KV via `/api/tasks`. Each user only sees their own tasks.
- **Admin — User management** — visible to admins only: create accounts (any role), enable/disable accounts (instant logout), delete users, look up account details.
- **Other pages (Products, Categories, Orders, Reports, ZNS settings)** — placeholder pages showing "No data yet".
- **Dark mode** — toggle on the login page and in the header; persisted in localStorage (`myhub.theme`).
- **Sidebar** — blue background `#0047ad`, collapsible, logo `/logo.png`, navigation menu.

## Architecture

```
┌──────────── FRONTEND (React SPA) ─────────────┐
│  Login.tsx → AppLayout (sidebar/topbar)       │
│  ├── Dashboard.tsx   (Tasks)                  │
│  └── AdminUsers.tsx  (admin only menu)        │
└──────────────────┬────────────────────────────┘
                   │ fetch /api/* (Bearer token)
┌──────────────────▼────────────────────────────┐
│  BACKEND — Cloudflare Pages Functions         │
│  /api/auth/login · /api/auth/register         │
│  /api/tasks · /api/tasks/:id                  │
│  /api/admin/users                             │
└──────────────────┬────────────────────────────┘
                   │ KV binding "PRODUCTS"
┌──────────────────▼────────────────────────────┐
│  Cloudflare KV                                │
│  user:<email> · session:<token> · task:<id>   │
└───────────────────────────────────────────────┘
```

No database server — all data lives as JSON values in KV.

## Backend (Cloudflare Pages Functions + KV)

- Functions under `functions/api/*` handle every `/api/*` request; shared helpers live in `functions/_lib/`
- KV namespace **PRODUCTS** stores:
  - `user:<email>` → `{ email, name, role, salt, passwordHash, createdAt, disabled? }`
  - `session:<token>` → `{ userId }` (TTL 7 days)
  - `task:<id>` → `{ id, userId, title, departments, status, deadline, images, createdAt, updatedAt }`
- Binding declared in `wrangler.jsonc`; type `Env` generated by `npm run cf-typegen` (`worker-configuration.d.ts`)

### Auth & security flow

1. `POST /api/auth/login` looks up `user:<email>`, rejects disabled accounts, hashes `SHA-256(salt:password)` and compares with the stored hash.
2. On success a random UUID token is stored as `session:<token>` (7-day TTL) and returned together with the public user object.
3. The client sends `Authorization: Bearer <token>` on every subsequent request; API handlers call `requireUser()` / `requireAdmin()`.
4. Invalid/expired tokens return 401 → the client redirects back to Login.
5. Disabling or deleting a user revokes all their sessions immediately (`revokeUserSessions`).

### Roles & permissions

- `admin` — full access + user management (`requireAdmin()` enforced server-side)
- `user` — own tasks only (tasks are filtered by `userId`)

## Local development

Run two terminals in parallel:

```bash
# Terminal 1 — API + local KV emulation (port 8788)
npm run dev:api

# Terminal 2 — Vite dev server (port 5173)
npm run dev
```

Open http://localhost:5173. Vite proxies every `/api/*` request to port 8788 (see `vite.config.ts`), so the frontend code calls relative paths exactly like in production.

- Local data lives in `.wrangler/state/` (gitignored) and never touches Cloudflare.
- If login requests hang forever, a stale `workerd` process is probably holding port 8788:

  ```bash
  lsof -nP -iTCP:8788 -sTCP:LISTEN   # find PID
  kill -9 <PID>                       # kill it
  npm run dev:api                     # start again
  ```

## Migrate legacy tasks from localStorage

One-time browser-console snippet (only needed for very old data):

```js
const oldTasks = JSON.parse(localStorage.getItem('myhub.tasks') || '[]');
let success = 0;
for (const t of oldTasks) {
  try {
    await fetch('/api/tasks', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        title: t.title,
        department: t.department || 'Dev',
        status: t.status || 'new',
        deadline: t.deadline || null,
        images: t.images || [],
      }),
    });
    success++;
  } catch (err) {
    console.error('Failed to migrate task:', t.title, err);
  }
}
console.log(`Migrated ${success}/${oldTasks.length} tasks`);
localStorage.removeItem('myhub.tasks');
localStorage.removeItem('myhub.deletedTasks');
localStorage.removeItem('myhub.tasks.view');
location.reload();
```

## Styling conventions

No separate `.css` files. Styles are embedded directly inside `.tsx` files as template-string constants rendered via a `<style>` tag (e.g. `const styles = \`...\`` + `<style>{styles}</style>`). Shared classes (table, cells, search) live in `AppLayout.tsx`.

Dark mode relies on the `data-theme` attribute on `<html>` (set by `ThemeProvider`). Components use `[data-theme='dark']` selectors to override light-theme colors to match antd's dark theme.
